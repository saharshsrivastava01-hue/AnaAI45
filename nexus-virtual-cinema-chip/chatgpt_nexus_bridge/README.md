# ChatGPT ↔ NEXUS Render Bridge

This small API gives a Custom GPT Action a controlled way to start and inspect the
existing GitHub Actions renderer. It does **not** make the virtual chip independent
of physical compute: GitHub-hosted runner CPU time executes the software/RTL jobs.

## Deploy

Deploy this directory as a Python web service with:
- Build: `pip install -r requirements.txt`
- Start: `uvicorn app:app --host 0.0.0.0 --port $PORT`
- Root directory: `nexus-virtual-cinema-chip/chatgpt_nexus_bridge`

Set these environment secrets on the host:
- `GITHUB_TOKEN`: GitHub fine-grained token scoped only to this repository, with Actions: Read and write (and repository metadata read).
- `NEXUS_CHATGPT_API_KEY`: a long random secret generated by you.
- Optional: `NEXUS_GITHUB_REPO`, `NEXUS_GITHUB_BRANCH`, `NEXUS_WORKFLOW_FILE`.

Do not commit secrets. Use HTTPS. Restrict the service to your own GPT and rotate the
API key if it is exposed. GitHub Actions consumes runner minutes and may have plan
limits; this is not a zero-cost guarantee.

## Connect a Custom GPT

After deployment, open the GPT editor → Configure → Actions → Import OpenAPI and
paste the deployed URL plus `/openapi.json`. Configure API-key authentication using
Bearer and the value of `NEXUS_CHATGPT_API_KEY`. The generated schema exposes:
- `POST /render` to dispatch the fixed NEXUS workflow on the fixed branch.
- `GET /runs/{run_id}` to inspect progress.
- `GET /runs/{run_id}/artifacts` to list output artifacts.

The current repository workflow has a fixed 120-frame demo render. The bridge does
not pretend arbitrary frame/FPS settings are applied; workflow inputs must be added
before those become configurable. The render artifact must complete successfully
before it can be downloaded from GitHub Actions.

pip install -r requirements.txt
